# 日志判读与常见问题

> 这个项目的日志是**设计成能当证据用的**。本文按“你看到什么”组织，
> 直接查到对应结论，不用通读。

---

## 一、快速判读表

### 启动阶段

| 日志 | 含义 | 下一步 |
|---|---|---|
| `==== BL v0.2 (A1FORCE=0) ====` | BL 版本正常，无强制搬运 | ✓ |
| `==== BL v0.2 (A1FORCE=1!) ====` | **诊断开关没关**，每次上电都会搬 STAGING | 改回 0 重烧（P21） |
| `pending install -> verify staging` | BL 认为有待安装镜像 | 若是意外 → 见“上电自动搬运” |
| `[VER] STAGING fail rc=12` | STAGING 里没有有效镜像 | 正常（没有待装镜像时） |
| `A2: apply staging -> app` | 正在搬运 | ✓ |
| `apply FAIL rc=N, stay in BL` | 搬运失败，**必须重新烧录** | 检查供电与 Flash |
| `jump entry via-base=75` | 入口字节校验通过 | ✓ |
| `jump entry` 后面没有 APP 日志 | 跳过去跑飞了 | 查 APP 入口/布局（P04） |

### 联网阶段

| 日志 | 含义 |
|---|---|
| `[HOTA] bearer UP` + 真 IP | PDP 激活成功 |
| `+SAPBR: 1,3,"0.0.0.0"` | **没插卡 / 没注网**（注意：引号齐全但 IP 是 0） |
| `[HOTA] act rc=2 (maybe up)` | 承载可能已起，需下游证据确认 |
| `[MQ] TCP/TLS up (CONNECT OK)` | TLS 握手完成 |
| `[MQ] MQTT session up (CONNACK OK)` | MQTT 会话建立 |
| `[MQ] state N -> M` 停住 | 看最后停在哪个状态，对照状态机 |
| `CONNECT OK` 但 `MCONNECT` 后立刻 `ERROR`+`CLOSED` | **漏了 SNI**（`SSLCFG="hostname",88,"域名"`） |

### 接收阶段

| 日志 | 含义 | 下一步 |
|---|---|---|
| `urc [……] n=61` | 完整一行 | ✓ |
| `urc [……] n=51` | 行内丢了字节 | 看 P10/P11 |
| `urc [] n=0` | 收到字节但没凑成行 | 正常（碎片/心跳残留） |
| `urc len 31/32 drop` | 长度校验不过（模组侧抖动） | 会自动重订阅 |
| `ver line damaged, resub N` | 已安排重订阅 | 观察 N 是否递减到 0 |
| `urc payload not a version` | 载荷不是 `<m>.<m>.<p>|url` | 检查发布内容 |
| `urc m=0 t=0` 且 `n=0` | 从没收到过完整行 | 查接收路径 |

### 下载阶段

| 日志 | 含义 |
|---|---|
| `chunk N code=206 len=1024` | 正常分片 |
| `code=601` | 网络错误（没卡/没注网/PDP 没起），**与 URL 无关** |
| `code=602` | 内存不足 ⇒ 必须分片（`BREAK/BREAKEND`） |
| `code=404` | URL 失效或路径错 |
| `code=0 len=601` / `code=99` | 应答错位（偶发，重试即可） |
| `reconnect` 计数上升 | 会话被拆（多半是 OTA 期间 MQTT 没停） |
| `rerun` 计数上升 | 单片重取 |
| `lead=N B skipped` | 数据体有前导垃圾（framing 问题） |
| `chunk0 head is not OTAI -> refetch` | 首片认不出，自动重取 |
| `header: hdr=64 total=49152` | 镜像头解析正常 |

### 校验与安装

| 日志 | 含义 |
|---|---|
| `stg crc ok, body 49088 B` | 落地内容完整 |
| `stg crc now=X / want=Y` | 不一致。now 错 = 正文被改写；只有 want 缺 = 头没写进去 |
| `APPLY OK len=49088 crc=…` | 搬运完成且回读一致 |
| `A3 commit: new firmware confirmed` | 新固件自证，回滚窗口关闭 |
| `commit rc=0 succ=0` | 提交成功 |

## 二、常见问题

### Q1. 重新烧了固件，上电却"自动搬运"，APP 一次都跑不起来

**这是本项目最贵的一个坑（P21）。**

两个前提叠加：

1. STC-ISP 只覆盖 IAP `0x10000` 以上，**不擦 STAGING 与 PARAM**，所以上次 OTA 的镜像还在；
2. BL 里有个诊断开关 `BL_OTA_A1_FORCE = 1`，让 BL **每次上电都无条件校验并搬运 STAGING**。

于是新烧的 APP 被 STAGING 里的旧镜像覆盖，表现极像"烧录没生效"。

**怎么确认**：看第一行是不是 `BL v0.2 (A1FORCE=0)`，以及有没有 `pending install`。

**怎么解决**：
- 用修复后的 BL（`A1FORCE=0`）；
- 要彻底干净，烧录时勾 **整片擦除**（连 STAGING/PARAM 一起清）。

---

### Q2. 服务器版本永远显示成 `0.7.0`，patch 恒为 0

**原因**：接收路径把行写坏了。典型形态是 `0.7.4` 被写成 `0.7..`，
而旧解析器在“第二段之后”没有强制要求 `.`，于是第三段读到 `.` 不是数字 ⇒ patch = 0。

**现在已加固**：
1. 解析器严格化（第二段后必须是 `.`，第三段至少一位数字，否则整条丢弃）；
2. `urc [%s] n=%u` 把原始行打出来 —— 一眼就能看出是行坏了还是解析坏了；
3. 坏行自动重订阅。

**判断依据**：`n=61` 是完整，`n<61` 是丢字节。

---

### Q3. `+HTTPACTION` 返回 601

**不是 TLS 问题，也不是 URL 问题。** 601 = 网络错误：

- 没插卡 / 卡没激活
- 没注网（`AT+CGREG?` 看分组域注册，**不是 `CREG`**）
- PDP 没起来（`AT+SAPBR=2,1` 查 IP）

**注意**：`+SAPBR: 1,3,"0.0.0.0"` 虽然**引号齐全**，但 IP 是 `0.0.0.0` ——
任何"靠引号判 IP"的写法都会误判成已连接。

判据必须是：**先要求 Status == 1，再扫“四段 1~3 位数字、点分隔、至少一个非零”的形状。**

---

### Q4. `+HTTPACTION` 返回 602

内存不足。模组 HTTP 响应缓冲只有 3356 B，整包 GET 必爆。
必须 `BREAK` + `BREAKEND` 分片，且服务器支持 Range。

---

### Q5. 下载中途 `modem silent, reopen failed`

HTTP 与 MQTT 共用模组的 SSL 上下文。OTA 期间只要 MQTT 还在发
`MCONFIG` / `SSLMIPSTART`，HTTP 会话就会被拆掉。

**做法**：进入 OTA 前让 MQTT 彻底让位（本项目用 `MQ_ST_HOLD`）。

---

### Q6. 设备连不上 MQTT，但 PC 客户端用同一套凭据能连

**先查 SNI。**

MQTT over TLS 必须发：

```
AT+SSLCFG="hostname",88,"<域名>"
```

漏了照样能拿到 `CONNECT OK`，但 `MCONNECT` 会在 62 ms 后 `ERROR` + `CLOSED`，
CONNACK 永不到达。

根因：Serverless 靠 SNI 路由实例；而 `seclevel=0`（不校验证书）把错误掩盖了，
问题从 TLS 层推迟到 MQTT 层，表现成“凭据没错就是连不上”。

---

### Q7. 日志打出 `!!ARGN!!` 或明显的垃圾值

日志系统的**宏名里的数字必须等于可变参数个数**，且一行最多 2 个值。

```c
LOG_I2(TAG, "urc [%s] n=%u", g_urc, (u16)g_urcn);   /* 2 个值，用 I2 */
```

写错会数组错位，打出相邻变量的内容 —— 看起来像“固件乱码”，其实是打印错。

---

### Q8. 同一份代码，两次构建 md5 不一样

说明存在**未定义行为**，不是“编译不稳定”。

常见原因：overlay 没关、参数块重叠、`static xdata` 未显式初始化、
某个变量地址依赖了对齐的偶然性。

**这是最该重视的信号** —— 本项目历史上多次靠“两次 md5 不一致”抓到真问题。

---

### Q9. `error C249: 'DATA': SEGMENT TOO LARGE` / 代码放不下

看 `.map` 的 `Program Size`：

```
code=40549  const=6937   →  47486 / 48640，余 1154 B
```

APP 的 48 KB 是 **ECODE + HCONST 共用**，不是各 48 KB。
空间不够时的处理顺序：

1. 先删**全工程 0 调用点**的函数（本项目靠删 6 条老通路省出 1466 B）；
2. 关掉诊断/取证用的大段代码（本项目有 `AT_DIAG_LEGACY` 开关，省 4.5 KB）；
3. 合并重复的字符串常量；
4. 最后才考虑砍功能。

---

### Q10. 上电串口一个字节都没有

按这个顺序查：

1. **看门狗**：STC32G 上电就在跑狗（不管代码有没有初始化它）。
   不能关喂狗，一关就是复位循环。要关的是“初始化”（`bsp_wdt_init` 会改分频）。
2. **时钟**：`fosc` 打印是否出现。没出现说明卡在时钟初始化。
3. **串口脚**：日志是 UART1（P3.0/P3.1），**这两脚也被 STC-ISP 占用**，
   下载时必须拔模组线，否则冲突。
4. **波特率**：115200 8N1。

## 三、判读的三条元规则

1. **只有“线路静默时间”能证明丢字节。**
   “这一圈干了什么”不行 —— 任何周期性重活都会按自己的周期吃字节。

2. **行尾校验和只能证明线路没坏，不能证明内容对。**
   和值错 = 抄写/桥接错误；和值对但内容怪 = 才去怀疑固件。

3. **“完全没反应且一行日志都没有” ⇒ 先怀疑根本没进那个函数。**
   判据：连 `ignored` 类分支都没打出来。
   （本项目为此误判过两次：一次是宏同名导致行缓冲只有 8 B，一次是 pending 门禁把 URC 全倒了。）

## 四、调试期绝对不要做的事

| 禁止 | 原因 |
|---|---|
| 两个 TX 同时接 MCU 的 RXD（桥接监听） | 两推挽对拉会**改写字符**，`+SAPBR` 变成 `+AAB`，把你引向完全错误的结论 |
| 在 `data_poll()` 里打日志 / 延时 / 等命令 | 一个字节 87 µs，任何阻塞都整字节丢 |
| 用 `bsp_timer_delay_ms()` | 依赖 Timer0 中断，APP 里 `EA=0` ⇒ 卡死但复位不了 |
| 把临时开关留在代码里过夜 | 见 P21，一个 `=1` 能让整套升级链路失效 |
| 凭“应该没问题”下结论 | 每条结论都要有日志/CRC/寄存器级证据 |
