# 架构说明

> 目标：在 **128 KB Flash / 8 KB xdata / 256 B 栈 / 无中断** 的约束下，
> 做出一套可维护、可自愈的双区 OTA。本文解释“为什么这么切”，不只是“切成了什么”。

---

## 1. 分层

```
┌─────────────────────────────────────────────────────────┐
│ APP/          应用层：自检、AT 启动、主循环、MQTT 业务、A1 造镜像 │
├─────────────────────────────────────────────────────────┤
│ OTA/          OTA 业务：状态机、镜像校验/搬运、跳转、分区表       │
├─────────────────────────────────────────────────────────┤
│ DRV/          外部器件：AT 命令引擎、HTTP 下载引擎               │
├─────────────────────────────────────────────────────────┤
│ BSP/          芯片外设：时钟/GPIO/串口/定时器/看门狗/Flash IAP   │
├─────────────────────────────────────────────────────────┤
│ COMMON/       与芯片无关：日志、CRC32、参数区、环形缓冲、OTA 类型 │
└─────────────────────────────────────────────────────────┘
```

**依赖方向严格向下**。`COMMON` 不认识 `BSP`，`BSP` 不认识 `OTA`。
这条纪律的实际价值：换芯片时只需要替换 `BSP`（见 `docs/PORTING.md`）。

## 2. 内存模型（本项目最反直觉的部分）

### 2.1 xdata 只有 7936 B 可用

```
CLASSES 必须显式写成 XDATA(0x1000-0x2EFF)
```

`0x0000-0x0FFF` 被 STC 的 IAP/系统区占用，`0x2F00` 以上是别的段。
**这条 `CLASSES` 要在三个地方保持一致**：`build_local.sh` 里两次 + 两个 `.uvproj`。
漏一处，链接器会静默换布局，症状是“变量地址莫名其妙”。

当前占用：`7430 / 7936`（余约 500 B）。

### 2.2 栈只有 256 B

- 任何 `> 32 B` 的对象**不许上栈**，一律 `static xdata`；
- 形参总大小 `> 8 B` 时 C251 会自动生成**参数块**（放在 xdata，不是栈），
  参数块之间可能互相复用 —— 这是 P02 里 overlay 问题的来源之一。

### 2.3 代码与常量共用 48 KB

APP 分到 `0x14200-0x1FFFF`（48640 B），**ECODE 和 HCONST 共用这一块**，不是各 48 KB：

| 项 | 当前 | 上限 |
|---|---|---|
| code | 40549 | — |
| const | 6937 | — |
| 合计 | **47486** | **48640**（余 1154 B） |

> 项目历史上多次撞到“余 65 B”这种极限。加功能前先看这里，别等链接器报错。

### 2.4 无中断

APP 全程 `EA=0` —— **中断向量在 BL，APP 里的同名 ISR 永远不会执行**。
所以：

- 时基只能轮询 Timer0 溢出位（`at_t0_poll()` / `at_ms()` / `at_delay_ms()`）；
- `bsp_timer_delay_ms()` 依赖 Timer0 中断 ⇒ 在 APP 里调它必然“卡死但复位不了”；
- 所有串口收数据都是 `while (RI)` 状态机，一个字节都不等。

## 3. 主循环与“线路静默窗口”

主循环是全项目最反直觉的设计，值得单独讲。

```c
/* app_main.c 内层循环（简化） */
t0 = at_ms();
for (;;) {
    if (at_pump() != 0U) {          /* 真从 SFR 取到字节 ⇒ 线路还在动 */
        t0 = at_ms();               /* 静默计时清零，不许离开 */
    } else {
        data_poll();                /* 填在 AT 的空档里，不整段让路 */
        if ((u32)(at_ms() - t0) >= APP_AT_QUIET_MS) break;
    }
}
mqtt_poll();
bsp_wdt_feed();
```

**为什么不是“每 N 圈做一次 MQTT”**：

UART3 只有 **1 个接收寄存器**，115200 下一字节 **87 µs**，
下一个字节到达就把上一个覆盖 —— 丢的是**整字节**，不是“丢一点”。

“每 8 圈做一次 MQTT”的写法下，那一次循环必然超过 87 µs，
于是**每 8 圈稳定吃掉一个字节**，且丢点在行内看起来是随机分布的。
抽稀（改成 1:4、1:16）都只是改变“多久吃一个”，治不了本 ——
因为**任何周期性重活都会按自己的周期吃字节**。

唯一可靠的判据是**线路自己的静默时间**：静默 1 ms = 11 倍余量，且与循环快慢解耦。

> 这也是本项目第三次修正对“丢字节”的认识。前两次分别是：
> ① 以为是线上丢（其实线是干净的）；② 以为是解析逻辑错（其实是行被撕碎）。
> 完整推演见 `docs/PITFALLS.md` 的 P10 / P11。

## 4. 日志系统

低资源平台上，日志的设计目标不是“好看”，而是**能当证据用**。

```c
LOG_I2(TAG, "urc [%s] n=%u", g_urc, (u16)g_urcn);
```

| 设计 | 原因 |
|---|---|
| 先填 `g_log_av[]` 数组，再按格式串消费 | 避免可变参数压栈（栈只有 256 B） |
| 宏名里的数字 **必须等于**参数个数 | 不然数组错位，打出垃圾 |
| 一行**最多 2 个值** | 行长限制 + 可读性 |
| 行尾 `*HH` 校验和 | 只能证明**线路没坏**，不能证明内容对 |
| `!!ARGN!!` | 参数个数写错的显式告警 |

**判读纪律**：行尾和值错 = 抄写/桥接错误；和值对但内容怪 = 才去怀疑固件。

## 5. 参数区：双份 + seq

`PARAM A`（`0xC000`）与 `PARAM B`（`0xC800`）各 2 KB，交替写。

```
读取：两份都读，各自校验 CRC，取 seq 更大的那份
写入：写到“不是当前有效份”的那一份，写完校验，再更新内存里的指针
```

这样**任何一次掉电都不会同时毁掉两份**。`seq` 用于判断新旧，
CRC 用于判断有效性——两者缺一不可（只看 CRC 会在两份都有效时选错）。

### 5.1 参数里的关键字段

| 字段 | 作用 |
|---|---|
| `seq` | 单调递增，用于在两份都有效时选新的 |
| `ota_state` | `IDLE / DOWNLOADING / VERIFYING / PENDING_REBOOT / COMMITTED / ROLLED_BACK` |
| `boot_try` | 启动失败计数，超 20 次由 BL 回滚（防无限擦写磨损 Flash） |
| `dl_offset` / `dl_total` | 断点续传。BL 也用它判断"上次是否下载完整" |
| `running_ver` / `pending_ver` | 当前运行版本 / 待生效版本 |

> ★ `COMMITTED` 是 **BL → APP 的交接点**：BL 搬完写 `COMMITTED`，
> 新 APP 自检通过后自己写 `IDLE`。掉电落在两步之间也没关系 ——
> `COMMITTED != PENDING_REBOOT`，BL 不会重复搬运，APP 再提交一次是幂等的。

## 6. 三个构建守门脚本

构建不是"编译通过就行"。这个项目的历史上，**链接成功但运行必错**的情况出现过多次，
所以把三类校验做成了构建流程的一部分：

| 脚本 | 检查 | 退出码 | 为什么必须有 |
|---|---|---|---|
| `check_layout.py` | `CLASSES XDATA(0x1000-0x2EFF)`；`?C_C51STARTUP` == `0xFF4000` | 6 | 布局被静默改掉 ⇒ 变量地址漂移 / 入口不对 |
| `check_overlay.py` | 两个工程都开 `NOOVERLAY`；参数块不重叠 | 7 | overlay 会让形参互相踩，且**不报错** |
| `merge_hex.py --check` | BL+APP 合并后连续性、身份、分区占用 | 8 | 防止把两份不匹配的 hex 拼在一起 |

```bash
bash tools/build_local.sh      # 一次跑完：编 BL → 编 APP → 三个守门 → 合并
```

**改完代码必须构建两次比对 md5。** C251 的布局对"加一行注释"级别的改动都可能敏感，
两次不一致说明存在未定义行为（本项目多次靠这条抓到问题）。

## 7. 镜像格式

```
偏移  长度  字段
0     4     magic "OTAI" (0x4F544149)
4     2     hdr_len = 64            （大端）
6     2     hdr_ver = 0x0001        （头格式版本）
8     1     ver_major
9     1     ver_minor
10    1     ver_patch
11    1     ver_build
12    4     img_len                 （正文长度，大端）
16    4     img_crc32               （正文 CRC32，大端）
20    4     entry                   （跳转地址）
24    4     reserved
28    8     target
36    4     hdr_crc32               （前 36 字节的 CRC32）
40    2     reserved = 0xFFFF
42    22    padding = 0xFF          （补齐到 64 B）
64    N     正文（APP 的 ECODE+HCONST）
```

**总长固定 `49152 = 64 + 49088`**。

`make_img.py` 在打包时会断言：首字节必须是 `0x75`（C251 启动指令），
否则说明 hex 错了或链接基址错了 —— 那种镜像"校验全过但一跑就飞"。
